Свобода внутри, контракт снаружи

У каждого гайда свой дизайн и свои анимации. Но любой гайд одинаково размечает секции и упражнения и подключает один трекер. Платформе неважно, как гайд выглядит.

2

Минимум сервисов

Vercel, Supabase и Paddle закрывают хостинг, базу, вход, файлы и подписки. Ни одного сервера, который нужно администрировать. За 10 дней это решает.

3

Трекинг — часть продукта

Прогресс чтения ученик видит в дашборде, поэтому он хранится в своей базе. PostHog нужен команде для решений: воронки, удержание, конверсия из пробного в платный.

4

Карты — источник истины

Города, юниты и порядок уроков строятся из карт грамматики и лексики скриптом. Поменял карту — план пересобрался, код трогать не нужно.

Что уже есть. Карты грамматики (158 тем) и лексики (152 темы) со стабильными id, часами, пререквизитами и привязкой к городам. Это готовый скелет базы данных. Гайды делаются с нуля под контракт платформы. Язык пока один — турецкий, но в схеме есть course_id, поэтому второй язык потом добавляется без переделки.

Построитель плана: карты → города и юниты
// scripts/build-plan.ts — запускается в CI,
// когда меняется любая из карт
for (const city of route) {          // A1 Стамбул … C1 Самсун
  plan.push(arrival(city))             // только A2 и B2

  // грамматика — по order, граф пререквизитов
  const spine = topoSort(grammar[city.level])

  // лексика встаёт после своей грамматики
  for (const v of vocab[city.level])
    insertAfter(spine, v.recommended_after_grammar, v)

  // режем на юниты по 5–7 уроков
  plan.push(...chunk(spine, { min: 5, max: 7 })
    .map(withPractice).map(withUnitTest))

  plan.push(cityStop(city), tools(city), levelTest(city))
}
// результат → таблицы units и lessons в Postgres;
// админ может вручную подвинуть урок (override)

Правила открытия уроков

жёстко

Грамматика

Тема открыта, когда пройдены её пререквизиты из карты. CI проверяет, что в графе нет циклов.

мягко

Лексика

Рекомендована после своей грамматики (recommended_after_grammar), но не блокируется.

всегда

Прибытие и повторение

Открыты сразу. Прибытие даётся готовыми фразами, повторение слов доступно в любой момент.

по тесту

Следующий город

Открывается тестом уровня. Тест при регистрации может сразу отправить ученика в нужный город.

Прогресс в часах, а не в процентах. У каждой темы в карте есть часы, у уровня — модель: уроки, повторение, тесты. Поэтому дашборд может сказать «до Измира ≈ 37 часов — около трёх месяцев при 25 минутах в день». Темы, у которых ещё нет гайда, показываются как «скоро» и не мешают проходить город.

Что изменилось в 2025–2026 и важно не пропустить

Next.js 16: proxy.ts

middleware.ts переименован в proxy.ts и по умолчанию работает на Node.js. Кэш включается явно: cacheComponents: true и "use cache".

Supabase: новые ключи

Ключи sb_publishable_… и sb_secret_… вместо anon и service_role — старые отключают в конце 2026. Подпись JWT асимметричная, проверка через getClaims().

GSAP теперь бесплатный

С апреля 2025 все плагины бесплатны и для коммерческих проектов. Запрещено только делать на нём конструктор анимаций, конкурирующий с Webflow.

Эти детали прописаны в CLAUDE.md, чтобы Claude Code не писал код по устаревшим туториалам.

Почему не другие варианты

Vue / Nuxt

Нормальный фреймворк, но меньше готовых компонентов, а ИИ-ассистенты пишут его хуже, чем React.

Firebase

NoSQL: связи «ученик — тема — секция» и аналитика в нём тяжелее. На свой сервер в РК не перенести.

Stripe

Не работает с продавцами из Казахстана.

Свой сервер, Docker, Kubernetes

Администрирование съест несколько дней из десяти. Нужно только для плана Б.

Отдельный бэкенд на NestJS или Go

Второй проект, второй деплой. Next.js и Postgres-функции закрывают всё, что нужно.

Местный эквайринг сразу

Freedom Pay или TipTop Pay дешевле по комиссии, но подписки придётся писать самому. Это после запуска.

Схема

Как всё связано

Ученик работает в приложении. Гайд открывается внутри приложения во весь экран, как урок в Duolingo. Сервер отдаёт гайд только тем, у кого есть доступ. События чтения идут через приложение на сервер и в Postgres.

← Схему можно листать вбок →

Чтение. iframe запрашивает /g/a1.dative/v1 на том же домене. Сервер проверяет доступ и отдаёт HTML из приватного бакета. Без доступа — 403 и пейволл.

Трекинг. tracker.js сообщает приложению о секциях и ответах. Приложение добавляет пользователя и раз в 30 секунд отправляет пачку событий на /api/track.

Публикация. Новый гайд — мерж в репозиторий. CI проверяет, озвучивает, кладёт в Storage и синхронизирует каталог. Релиз приложения не нужен.

Фронтенд

HTML, React, Vue или что-то другое

Платформа и гайды решают разные задачи, поэтому одна технология на всё — ошибка. Платформа — веб-приложение с входом, подпиской, состоянием и данными. Гайд — длинная страница-история с тяжёлой анимацией, которую читают сверху вниз.

Платформа
React на Next.js 16
  • Быстрее всего с Claude Code. Нейросети лучше всего пишут React и Next.js — при сроке 10 дней это решает.
  • Всё для SaaS из коробки. Серверные компоненты, Server Actions, кэш каталога, proxy.ts для проверки входа.
  • Дизайн с макета — из готового. shadcn/ui, Motion, Recharts закрывают большую часть экранов.
  • Найм. React-разработчиков на рынке больше всего.
Гайды и игры
HTML + CSS + GSAP и общий kit
  • Без сборки. Гайд — один index.html. Claude Code генерирует такую страницу быстрее и надёжнее всего.
  • Общее не копируется. Упражнения, озвучка, карточки слов и трекер — web components из kit.js, подключаются одной строкой.
  • Один код упражнений. React 19 понимает web components, поэтому упражнение в гайде и в уроке «Практика» — одно и то же.
  • Быстро на слабом телефоне. Без фреймворка: только GSAP и код гайда.

Правила вёрстки

  • Ширины — через max-width и clamp(), фиксированных ширин блоков нет.
  • Компоненты подстраиваются под свой контейнер (@container в Tailwind 4): карточка одинаково хорошо выглядит в сайдбаре и в центре.
  • Высота экрана — dvh вместо vh: адресная строка Safari и Chrome не обрезает контент.
  • Кнопки не меньше 44×44 px; hover — только для мыши: @media (hover: hover).
  • Шрифт в полях ввода не меньше 16 px — иначе iPhone приближает страницу.
  • Иконки — SVG, картинки — AVIF/WebP с версиями для Retina.

Гайд на разных экранах

  • Телефон: во весь экран, верхняя панель 48 px, кнопка «назад» Android закрывает гайд, а не уходит с платформы.
  • Ноутбук и iPad горизонтально: гайд не шире 1100 px по центру.
  • От 1600 px: слева оглавление секций с галочками, справа слова гайда.
  • Медиазапросы гайда смотрят на ширину iframe, поэтому гайд тоже верстается mobile-first.
  • При повороте экрана анимации GSAP пересчитываются; при prefers-reduced-motion показывается итог без анимации.
  • content:check снимает каждый гайд на 360, 768, 1280 и 1920 px.

CI не пропустит гайд, если

  • topic не найден в карте или уровень гайда не совпадает с уровнем темы;
  • секция в разметке не совпадает с guide.json или ключ повторяется;
  • на 375 px есть горизонтальный скролл или ошибки в консоли (Playwright);
  • JS + CSS гайда тяжелее бюджета — например, 400 КБ без медиа;
  • у упражнения нет темы и навыка — тогда дашборд не поймёт, что у ученика слабое.

Ключи секций — навсегда. Прогресс хранится по ключу, а не по номеру. Если потом вставить секцию в середину, у тех, кто уже читал гайд, прогресс не съедет.

Доступ к гайдам по подписке

Ученик открывает урок, iframe запрашивает /g/a1.dative/v1
Запрос идёт на тот же домен — cookie сессии уходит сама
Сервер проверяет доступ: пробный период или подписка
Читает HTML из приватного бакета Supabase Storage
Отдаёт гайд: кэш в браузере, встраивание только в платформу

Без доступа сервер отвечает 403, приложение показывает пейволл. Аудио и картинки лежат в публичном бакете с CDN: без HTML гайда они бесполезны, зато кэшируются. Когда трафик медиа превысит 250 ГБ в месяц, его можно перенести в Cloudflare R2 — меняется одна переменная.

Как добавить игру

Папка public/games/<id>/ + game.json → мерж → Vercel выкладывает, CI регистрирует игру в каталоге. Через пару минут она в разделе «Игры». Позже — загрузка zip в суперадминке.

Безопасность

Игра запускается в iframe с sandbox="allow-scripts": у неё «чужое» происхождение, поэтому даже сторонний код не прочитает cookie и не сходит в API от имени ученика. Очки проверяет сервер, XP ограничен в день.

Что можно копировать

Механики («найди пару», wordle, виселица) не защищены — их можно брать. Чужой код, графику и названия — нельзя. Open-source игры с лицензией MIT или Apache можно адаптировать, сохранив лицензию.

Зарегистрировался, не платит. Доступ по правилам пробного периода.

Как это устроено

Роль
app_role в профиле: user, admin, superadmin. Попадает в JWT через Custom Access Token Hook, RLS читает её оттуда.
Доступ
«Пробный» и «ученик» — не роль, а статус: trial, student, expired. Считается из trial_ends_at и подписки. Если бы это была роль, её пришлось бы переключать руками — и кто-то бы забыл.
Запись
Прогресс, XP и доступ меняет только сервер: /api/v1 и Postgres-функции. «Урок пройден → XP → стрик → следующий урок» — одна транзакция.
Защита
Для админа и суперадмина обязательна двухфакторная защита (TOTP в Supabase Auth). Каждое их действие пишется в audit_log.
RLS: ученик видит себя, админы — всех
alter table user_guide_progress enable row level security;

create policy "свой прогресс"
  on user_guide_progress for select
  using (user_id = (select auth.uid()));

create policy "админы видят всех"
  on user_guide_progress for select
  using (((select auth.jwt()) ->> 'app_role')
         in ('admin', 'superadmin'));

-- политик insert/update нет:
-- писать может только сервер (секретный ключ)

-- суперадмин — только миграцией:
update profiles set app_role = 'superadmin'
 where id = '<твой user id>';

Безопасность

  • RLS на каждой таблице; секретный ключ Supabase только на сервере и в CI
  • postMessage: проверка источника с обеих сторон
  • Гайды встраиваются только в платформу (frame-ancestors 'self')
  • Лимит запросов на /api/track и вход; подпись вебхуков Paddle проверяется
  • XP и прохождение считает сервер, клиент сообщает только факты
  • Ежедневные бэкапы; минимум личных данных; удаление аккаунта одной кнопкой

Нужны ли CI/CD и Docker

CI/CD
Да, но минимальный
  • Vercel сам деплоит: каждый push → превью-ссылка, main → прод. Настраивать нечего.
  • GitHub Actions, один файл. На PR — типы, линтер, Vitest, Playwright по превью. На main — миграции, публикация изменённых гайдов, content-sync.
  • Миграции БД — только из Git. Схему на проде руками не трогаем никогда.
  • Три окружения: локально, превью (отдельный проект Supabase), прод.
Docker
Нет — для деплоя не нужен
  • Деплой: Vercel и Supabase сами управляют серверами. Dockerfile писать не нужно.
  • Локально: Docker Desktop или OrbStack нужен только как движок для supabase start.
  • План Б: если юрист скажет хранить данные в Казахстане — VPS в РК (Yandex Cloud kz1, PS Cloud) и Docker Compose: Next.js + self-hosted Supabase. Это +3–5 дней работы.
  • Kubernetes: нет. При такой нагрузке это лишняя сложность.
.github/workflows/ci.yml — суть
on: [pull_request, push]
jobs:
  check:          # каждый PR
    - pnpm typecheck && pnpm lint
    - pnpm test               # Vitest: domain, RLS
    - pnpm guide:check --changed
    - pnpm e2e --base-url=$PREVIEW_URL
  release:        # только main

    - pnpm content:publish --changed

    - pnpm content:sync       # каталог → Postgres

Мониторинг

  • Sentry: ошибки клиента и сервера, алерт в Telegram
  • Uptime-монитор на главную и /api/health — проверка раз в минуту
  • Логи Vercel и Supabase; отдельный алерт на ошибки /api/track и вебхуков Paddle

Трекинг

Как узнать, до какой части дочитан гайд

Гайд — отдельная страница в iframe, он не знает ни про ученика, ни про базу. Он только сообщает факты через postMessage, а приложение дописывает пользователя и отправляет данные на сервер. Поэтому 310 гайдов не зависят от кода платформы.

Когда секция считается прочитанной

Если засчитывать секцию при простом показе, быстрый скролл до конца даст «100% прочитано». Поэтому учитываем время:

секция в фокусеи активное время ≥ 30% расчётногогде расчётное = data-words ÷ 150 слов в минуту

Гайд пройден, когда прочитано не меньше 80% секций и сдан тест в конце. Кнопка «Продолжить» на маршруте ведёт ровно в последнюю секцию.

Слой 1 — своя база

Всё, что видит ученик: секции, время, ответы, стрики. Сырые события лежат в таблице с партициями по месяцам и живут 90 дней, агрегаты — всегда.

Слой 2 — PostHog

Только ключевые события: регистрация, первый гайд, пробный → оплата, город пройден, отмена подписки. Детальные события туда не шлём: при 5 000 учеников в день это десятки миллионов событий и сотни долларов в месяц.

Нагрузка

Хватит ли мощности

Kit, игры и медиа раздаёт CDN, гайды кэшируются в браузере, каталог — в кэше Next.js. До базы доходит почти только личное: прогресс и события. Для Postgres это мало.

~500учеников онлайн в пик — около 10% от 5 000 в день
~17/сзапросов трекинга в пик при батче раз в 30 с
~5 млнсобытий в месяц, около 35 на ученика в день
×10запас: стек тянет 50 000 в день без переделки

Три слоя кэша

~95%
CDN и браузерKit, игры, аудио, картинки — кэш навсегда. HTML гайда — в браузере на час.
~4%
Кэш Next.jsМаршрут, темы, метаданные. Сбрасывается при публикации.
~1%
PostgresТолько личное: прогресс, события, подписка, слова на сегодня.

Доли — оценка по трафику. Пики: вечер 19:00–22:00, рассылки, начало учебного года. Соединения идут через пулер Supavisor, чтобы serverless-функции не исчерпали лимит базы.

Ритм одного дня

  1. Утро: план на OpusPlan mode (Shift+Tab), промпт дня из PLAN.md. Читаешь план, правишь, утверждаешь.
  2. День: код на Sonnet/model → Sonnet. Одна задача — одна сессия; /clear между задачами, чтобы контекст не засорялся.
  3. После каждой фичиТесты, проверка на 375 px, коммит. Превью-деплой на Vercel.
  4. Вечер: ревью на Opus/code-review по изменениям дня, правки, мерж в main.
  5. ПараллельноВо второй сессии Sonnet генерирует гайды по одному промпту на тему.
Решить до старта

Вопросы, которые меняют стек

Их нужно закрыть до дня 1 или в первые дни: от ответов зависит, где хранить данные, как принимать оплату и что видит пробный пользователь.

Где хранить данные учеников

Закон РК требует, чтобы база с персональными данными граждан находилась в Казахстане. Юристы спорят, допустима ли копия за рубежом, но основная база в РК устраивает оба толкования. С поправками 2026 года место хранения базы ещё и нужно указывать в уведомлении регулятору.

Решение для 10 дней: Supabase во Франкфурте, минимум личных данных (только email и имя) и консультация юриста сразу. Если нужна локализация — план Б: Docker Compose (Next.js + self-hosted Supabase) на сервере в РК, например Yandex Cloud kz1 или PS Cloud. Код не меняется, это +3–5 дней.

Как принимать оплату

Stripe не работает с продавцами из Казахстана. Paddle работает: Казахстана нет в списке запрещённых стран, НДС РК он считает и платит сам, выплаты раз в месяц в USD или EUR.

Решение: Paddle на старте, Polar — если Paddle откажет (Казахстан есть в списке выплат Polar). Местный эквайринг (Freedom Pay, TipTop Pay) — после запуска, когда выручка оправдает работу над своими подписками.

Как устроен пробный период

Варианты: 7 дней полного доступа без карты или первые уроки Стамбула навсегда.

Рекомендация: 7 дней полного доступа без карты (считает платформа, а не Paddle), после — остаются первые уроки Стамбула и пейволл. Всё хранится в settings, суперадмин меняет без релиза.

Цены и тарифы

Месяц и год, валюта, цена с НДС или без.

Из-за фиксированной комиссии $0,50 выгоднее продвигать годовой тариф. Цены живут в Paddle, в базе — только их id.
